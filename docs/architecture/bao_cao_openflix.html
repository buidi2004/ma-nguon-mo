HỆ THỐNG XEM PHIM TRỰC TUYẾN OPENFLIX

Phát triển bằng Flutter Framework & PocketBase Backend-as-a-Service (BaaS)

Học phần: Lập trình Di động / Kỹ thuật Phần mềm
Nền tảng: Flutter 3.x, Dart 3.x, PocketBase
Kiến trúc: Clean Layered (Presentation - Service - Model)
Giấy phép: Mã nguồn mở MIT License
💡 HAI NGUYÊN LÝ CỐT LÕI CẦN NHỚ KHI THUYẾT TRÌNH:
  1. App chỉ hỏi PocketBase để lấy metadata phim (tên, mô tả, năm, thể loại, link poster, link video). PocketBase không gánh tải file đa phương tiện lớn.
  2. Video và poster được tải/stream trực tiếp từ máy chủ media chuyên dụng (CDN / Cloud Storage) chứ không đi vòng qua PocketBase.

1. Phân Tích Yêu Cầu

1.1. Yêu cầu chức năng (Functional Requirements - FR)

Mã Nội dung yêu cầu Mức độ ưu tiên
FR1 Hiển thị danh sách phim lấy từ server Bắt buộc
FR2 Hiển thị banner các phim có is_featured = true Bắt buộc
FR3 Nhóm phim theo thể loại, mỗi thể loại là một hàng cuộn ngang Bắt buộc
FR4 Tìm phim theo từ khóa trong tên hoặc nội dung mô tả Bắt buộc
FR5 Xem chi tiết phim (poster, mô tả, năm phát hành, thể loại) Bắt buộc
FR6 Phát video: play/pause, tua ±10s, thanh tiến trình, xoay toàn màn hình Bắt buộc
FR7 Quản trị viên thêm/sửa/xóa phim và đánh dấu nổi bật qua Admin UI Bắt buộc
FR8 Hiển thị trạng thái loading và thông báo lỗi khi mất mạng (fallback offline) Nên có

1.2. Yêu cầu phi chức năng (Non-Functional Requirements)

Nhóm tiêu chuẩn Nội dung quy định
Hiệu năng Tải danh sách một lần (fetch-once), tìm kiếm lọc tức thì trên máy (in-memory). Mục tiêu: màn hình chính hiện trong 1-2 giây trên kết nối 4G/Wifi.
Bảo mật Người dùng chỉ được đọc công khai (Public Read). Thao tác Create/Update/Delete khóa chặt chẽ, chỉ quản trị viên được ghi qua Admin UI.
Tương thích Hệ điều hành Android (xuất bản APK release độc lập), hỗ trợ tự động xoay ngang khi xem video.
Khả năng bảo trì Tách lớp độc lập models, services, screens, widgets để sửa một phần không ảnh hưởng phần khác.
Mã nguồn mở Dùng toàn bộ thư viện mở, giấy phép tự do MIT / Apache 2.0, tài liệu README đầy đủ.
Giới hạn phạm vi (Project Boundary): Ứng dụng không có đăng nhập tài khoản cá nhân, không có thanh toán trực tuyến, không có lịch sử xem qua cloud. Đây là bản demo tập trung cốt lõi vào trải nghiệm lướt và xem phim mượt mà.

2. Tác Nhân & Biểu Đồ Use Case

Tác nhân Use Case tương ứng
Người xem
(Không cần tài khoản)		 • UC1: Xem danh sách theo thể loại
• UC2: Xem banner nổi bật
• UC3: Tìm kiếm phim
• UC4: Xem chi tiết phim
• UC5: Phát phim
Quản trị viên
(Admin)		 • UC6: Thêm/sửa/xóa phim
• UC7: Đánh dấu phim nổi bật (is_featured)

Quan hệ giữa các use case khi vẽ sơ đồ:

  • UC3 <<extend>> UC1: Vì tìm kiếm là thao tác tùy chọn mở rộng trên danh sách phim.
  • UC5 <<include>> UC4: Vì phải mở thông tin chi tiết phim thì mới phát video được.
  • UC7 <<extend>> UC6: Vì gắn cờ nổi bật là tùy chọn khi thêm/sửa bản ghi phim.
  • Hệ thống ngoài (vẽ ngoài khung hệ thống): Máy chủ media (phục vụ streaming video & poster).

3. Phân Tầng Trong App Flutter

Tầng (Layer) Thành phần mã nguồn Trách nhiệm chính
Presentation HomeScreen, PlayerScreen, MovieCard Hiển thị dữ liệu lên giao diện và tiếp nhận cử chỉ chạm của người dùng.
Service PocketBaseService Duy nhất nơi biết URL server và cách gọi API mạng.
Model MovieModel Chuyển bản ghi JSON / RecordModel PocketBase thành đối tượng Dart.
Quy tắc phụ thuộc đơn hướng: Screen gọi Service, Service tạo Model. Screen không bao giờ gọi trực tiếp thư viện pocketbase. Nhờ vậy, nếu thay PocketBase bằng backend khác, bạn chỉ phải chỉnh sửa duy nhất một file pocketbase_service.dart.

5. Thiết Kế Giao Tiếp API

PocketBase tự động sinh REST API đầy đủ cho collection movies, không cần tự viết code backend.

Mục đích Phương thức và đường dẫn Chủ thể gọi
Lấy danh sách phim GET /api/collections/movies/records?sort=-release_year App Flutter
Lấy một phim GET /api/collections/movies/records/{id} App (nếu cần)
Tìm kiếm phía server GET .../records?filter=(title~'bunny') Phương án phụ
Thêm/sửa/xóa phim POST / PATCH / DELETE .../records Chỉ Admin qua Web UI

8. Quyết Định Thiết Kế & Đánh Đổi (Trade-offs)

Quyết định Lý do lựa chọn Đánh đổi & Cách xử lý
Video lưu ngoài, DB chỉ lưu link Gói miễn phí của PocketHost hạn chế dung lượng. Link .mp4 phát được ngay với tốc độ CDN tối đa. Phụ thuộc bên thứ ba, link hỏng là không phát được. Dự phòng link Google Cloud uy tín.
Tìm kiếm lọc trên máy Dữ liệu 8-10 phim, tìm tức thì không tốn request mạng. Không mở rộng được khi có hàng chục nghìn phim (lúc đó chuyển sang dùng filter API).
Tải danh sách một lần Đơn giản, ít lỗi gián đoạn giao diện. Dữ liệu không tự cập nhật nếu admin sửa khi app đang mở (bổ sung kéo xuống làm mới).
Không có đăng nhập Tập trung vào luồng xem phim trong phạm vi đồ án. Ai cũng xem được, chưa có cá nhân hóa (dành cho giai đoạn phát triển sau).
PocketBase thay cho tự viết backend Một file chạy, có sẵn REST API, Admin UI, SQLite. Ít linh hoạt hơn backend viết tay từ đầu nhưng tối ưu cho ứng dụng MVP FOSS.
Chewie bọc video_player Có sẵn giao diện điều khiển và fullscreen xoay ngang. Phải tự bổ sung thêm nút tua ±10s.

Về bảo mật: App không chứa API key hay mật khẩu nào, chỉ có URL server công khai. Quyền ghi bị khóa ở phía server, nên dù ai trích xuất hay dịch ngược file APK cũng không sửa được dữ liệu.

9. Rủi Ro & Hướng Phát Triển

Rủi ro tiềm ẩn Cách giảm thiểu đã thực hiện
Link video bên ngoài ngừng hoạt động Upload sẵn 2-3 phim vào trường file của PocketBase làm dự phòng; lưu trữ file video dự phòng.
Mất mạng khi đang demo Chuẩn bị video quay màn hình sẵn; app có sẵn cơ chế offline fallback (không bao giờ crash).
Instance PocketHost ngủ do không dùng Mở thử và gửi request đánh thức instance trước giờ báo cáo 10 phút.
Hướng phát triển (Đưa vào cuối slide): Đăng nhập và danh sách yêu thích (dùng collection users có sẵn của PocketBase), lưu vị trí đang xem dở, tìm kiếm phía server, bộ lọc theo năm, tải offline.
